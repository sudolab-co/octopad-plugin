# Running the distill

The distill writes each contact's card: its summary and the answers to the workspace's questions. Run its settings for the user through these tools rather than sending them to the settings page, and change one only on the user's instruction, after saying what it will cost. The directions, questions and nightly switch live in `crm_runs`.

- **Directions and questions.** Read them with `crm_runs` `get_directions`. Try a draft first with `preview_distill`. Then save with `set_directions`, each question key a lowercase slug of at most 40 characters. Put the directions and every question in one save: the saves a day that change what the model reads are limited. List earlier versions with `list_directions_versions`; restore one with `restore_directions`, at the cost of a save.
- **The nightly switch.** `get_schedule` reads it. `set_schedule` changes it and its `nightly_cap`, and only an organization owner or admin may. On, it is a recurring spend to confirm with the user. Off, nothing is folded on a schedule, so a requested re-fold waits.
- **Which field changes re-fold a summary.** `crm_fields` `set_refold` on a contact or company field; false suits a field that changes every day. Switching it makes every contact holding a value due one re-fold, one model call each inside the nightly cap. Where the organization has source sync, an adapter that declares `triggers_refold` for a field sets the flag again each time it registers.
- **Why a contact is due, or not.** `crm_runs` `explain_due` says for each contact whether the nightly job would fold it and why.
- **Re-fold later or now.** `request_refold` queues a re-fold of the chosen contacts for the nightly job, which folds nothing while its switch is off. `crm_runs` `launch` with kind `distill` folds now and bills now. Anything that can wait, leave to the nightly job.
- **Filtering on answers.** `crm_search`, `crm_contacts` `list` and `crm_segments` filters take `{field: "answers.<key>", operator: "eq", value: <an answer> or "unknown"}`. Only an answer to the current question matches, and a contact whose AI summary is off never does. `"unknown"` means the distill looked and found no evidence: a contact not yet folded under the current question matches nothing, `"unknown"` included. To pick prospect contacts by an answer, follow the outreach privacy gate in the skill's main file.
- **No AI summary.** When a person asks not to be summarised, `crm_contacts` `update` with `ai_summary_off: true`: the distill stops and every reader withholds the card, which is kept, not deleted. The record's brief stays readable and embedded, so never restate the withheld summary there. It is a member's switch, refused over an agent key. Where the organization has source sync, an adapter that owns `ai_summary_off_source` can switch a contact off too, and then only that adapter can switch it back on.
